# 免费额度与支持版方案

日期：2026-11-02。状态：作者评审稿，未写入限制代码，未开始销售。

## 1. 目标与当前阶段

先让普通用户长期完整使用，再由重度使用和自愿支持带来收入。当前 0.2.0 无额度限制、账号、付款或 AI；第一轮开源继续保持这个状态，不收预付款，不展示不可用的购买按钮。AI 与商业服务暂缓，开源后由作者自行邀请试用。

下面的数字是建议，不是现有版本的功能承诺。以后启用限制前，要先完成购买、激活与异常处理，并提前公布规则；不能把已经免费交付的旧版本变为必须付费才能使用。

## 2. 建议额度与价格

| 能力 | 永久免费基础版 | 未来支持版 |
|---|---|---|
| 同时进行中的项目 | 30 个 | 不设产品额度上限 |
| 未完成任务 | 500 条，子任务不单独计数 | 不设产品额度上限 |
| 每个自然月账单 | 1,000 笔，两个账本合计 | 不设产品额度上限 |
| 规划、习惯、清单、灵感、复盘 | 不设产品额度上限 | 相同 |
| 现有统计、导入导出、备份、主题和个性化 | 全部提供 | 相同 |
| 历史记录查看、编辑、完成、归档与导出 | 永久可用 | 相同 |
| 注册 | 本地功能无需注册 | 激活方式以后确定 |
| 价格 | ¥0，没有试用期限 | 建议 ¥99 一次性，尚未销售 |

30 个项目、500 条待完成任务及平均每天 30 多笔账单，意在给个人使用留出空间；这些数字没有经过真实用户研究，不能当成已证明能满足所有用户的结论。“不设产品额度上限”仍受本机性能与磁盘容量约束。

支持版解锁约定的本地容量，不承诺无限云服务、终身人工支持或无限 AI。已购买本地权益的离线持续使用、适用版本、设备范围、更新及退款规则必须在销售前明确。具体价格待作者确认。

## 3. 计数与数据保护

- 项目需要独立的进行中、完成、归档状态。完成或归档释放额度；重新启用按恢复后数量判断。当前模型没有完整的项目生命周期，必须先补齐，不能用“没有未完成任务”猜项目已经结束。
- 任务按实际未完成且未归档的主任务计数，跨所有项目合计；完成或正常归档释放额度。恢复时若超出，保留原记录并说明，不能静默丢失或修改完成状态。
- 账单按账单日期所属的自然月计算现存记录数，收入、支出及两个账本合计；编辑原记录不重复消耗。它是月记录容量，不是隐藏的终身创建次数。
- 换月后有新的 1,000 笔容量；历史记录保留，不一年后停止记账。备份恢复、导出及导入历史数据始终可用。导入导致已有记录超额时照常保存与查看，仅提示后续新建规则。
- 不追溯拦截现有数据，不为降到额度内要求删除记录。出现误判或激活故障，应可继续查看、编辑、完成及导出。
- 任何限制上线前覆盖所有创建入口，并让检查与保存使用同一数据快照；不能只拦工具栏按钮。公开客户端可以被修改，不能将本地计数当作防篡改系统。

## 4. 收费入口在哪里

固定入口：导航栏齿轮 → 设置 → “版本与支持”。保留八个业务导航，不增加“会员中心”主模块。

版本与支持页展示当前版本、免费权益、三项真实用量、支持版对照、价格与适用范围。将来销售就绪后才出现“购买支持版”和“已有授权，激活”；购买打开外部官方购买页，返回插件激活。付款处理不放在 GitHub，也不依赖 Obsidian 收款。

| 时机 | 呈现 |
|---|---|
| 正常使用 | 不弹广告，不占总览，不显示全站用量警告 |
| 某项达到 80% | 只在相关模块显示一行可关闭的用量提示，不打断操作 |
| 达到上限、尝试新建 | 在当前表单就地说明用量及可行动作，保留已填内容；提供“管理已有记录”与销售就绪后的“了解支持版” |
| 激活失败 | 原免费与已有数据权益继续可用，显示原因及重试入口 |

达到免费额度之后新增操作确实会受限，说明必须直说，不能用“免费无限使用”宣传。已有记录的访问与整理不能随之收费。

## 5. 收入预期与路线

宽松额度会降低被额度驱动的付费比例，这是本方案接受的取舍。收费的时间点在用户稳定使用并认可产品之后；界面入口本身不能制造购买理由。支持版收入更多来自重度用户及愿意支持官方维护的人，目前没有依据预测转化率或收入。

当前只发布完整免费版，收集反馈后再决定是否保留容量付费。购买与激活准备完成以前不执行限制，不为凑付费卖点拆走现有基础功能。未来 AI 可另行计费，但不是当前支持版的购买承诺。

目录分类也随真实能力变化：当前无任何付款入口可按 Free 申报；容量收费实际启用后按 Optional payment 披露。参见 [Obsidian FAQ](https://docs.obsidian.md/community-directory/faq)。
