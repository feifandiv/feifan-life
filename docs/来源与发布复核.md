# 来源与发布复核

日期：2026-11-02。对象：独立公开版 0.2.0。此记录是工程复核，不是法律鉴定或官方审核结果。

## 源码与构建边界

- 业务源码来自作者自用工程的公开版副本，保留项目、财务、清单及规划等模块；不是宣称获得外部插件官方身份的新分叉。清理范围是源码、默认配置和素材，不提交作者运行数据。
- 检查当前源码的 import、require、网络调用、HTML 写入及来源标记。未发现已署名却缺少许可的外部业务源码；无法据此证明每一行的最初创作来源。后续发现第三方来源时，必须补全其原始许可与通知。
- 通过 esbuild metafile 检查实际构建输入：仅 `src/` 与三张背景图片，唯一运行时外部模块是 Obsidian。开发工具的 `node_modules` 不随插件安装包分发。
- 自写 SVG 保留在数值图表中；模块图标统一由 Obsidian `setIcon` 提供。财务 SVG 金额中的用户货币符号改用 `textContent`，恶意标记回归测试通过。

- 模式扫描覆盖常见密钥、个人绝对目录和旧插件存储位置；它不替代人工复核。构建、下载验证及临时报告放在忽略目录，不进入源码仓库。

- 仅支持桌面，macOS 为已记录原生检查环境；Windows、Linux 与大数据性能仍需补充实机证据。

## 发布校验

`npm run build` 后运行 `npm run check:release`，检查版本映射、三个安装文件、语法、许可文本、离线背景、运行时依赖、源码映射及个人绝对目录，并记录 SHA-256。CI 与 Draft Release 使用同一组检查。

Draft Release 仅从 main 手动触发，要求同名版本 tag 精确指向所选提交。发布后的三个附件需要下载，逐个核对摘要及文件名。只有公开仓库与非草稿 Release 才能供一般用户下载；准备草稿不等于已开源上架。

## 仍需单独处理

正式社区提交需要作者的 Obsidian 账号、关联 GitHub，并处理目录实际给出的自动审核结果。天气服务商业许可、付费权益、账号、支付、激活和 AI 都属于后续商业阶段，不影响当前无收费版本的准备。
