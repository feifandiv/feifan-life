# 非凡 UI 1.1：设计与交互规范

更新：2026-11-02。配色身份：`palette-1`。本次为规范升级，插件实现版本仍为 `0.2.0`。白底 + 枣红方向已经用户确认，不重新发散皮肤方案。

## 1. 如何使用

本文件是当前设计规范；[改造说明](普适化改造说明.md)记录本产品副本的变化，测试报告记录实际通过的场景。**要求不等于实现，也不等于验收通过。** “必须 / MUST”为合入新 UI 的条件；“建议 / SHOULD”允许有理由的例外。例外须记录规则 ID、原因、范围与回收条件。

| 入口 | 职责 |
|---|---|
| `src/design-system/tokens.css` | 颜色、尺寸和明暗变量的唯一数值来源 |
| `src/design-system/components.css` 与公共 TS 组件 | 共享外观、行为和生命周期 |
| [design-tokens.json](design-tokens.json) | 从 CSS 生成的 token 索引，禁止手改 |
| [ui-contract.json](ui-contract.json) | AI 可读的规则 ID、检查方法与明确待办 |
| 发布工程说明 | 本副本不包含作者工作台、个人快照及历史截图；视觉资产的发布须另行核对授权 |

数值冲突以 token 源码为准，语义与行为以本文件为准；先修正冲突再合入。视觉文档中的演示不增加产品功能。旧 `06` 为历史皮肤方案，`07` 为 1.0 迁移记录，不再作为当前规则入口。

## 2. 设计目的与复用边界

面向每天反复使用的个人工作台：信息容易扫读，操作位置稳定，输入清楚，反馈及时。品牌感来自小面积枣红与一致的秩序。白灰承担大部分画布和辅助层级，不用四色平均铺满页面。

可复用核心规则使用 `FF-*`，非凡人生专属布局使用 `LIFE-*`。其他产品复用核心 token 与组件，再建立自己的业务布局；不照搬任务/账本模型，也不复制 Obsidian 宿主依赖。目前已有共享源码，尚未独立发布组件包。

## 3. 核心规则

### FF-01 / 唯一来源与作用域 / MUST

品牌原色 → 明暗语义 token → 公共组件 → 业务页面。业务 CSS 只消费公共 token，不新增页面专属颜色、圆角、阴影或明暗判断。新增语义先定义公共配方，再由相关页面共同使用。替换旧规则时移除被替代的定义，不不断追加覆盖。

主题只作用于 `.ff-ui[data-ff-mode]`；弹窗与菜单 portal 使用相同主题根。禁止向宿主 `body` 注入全局颜色。避免为压过主题而普遍添加 `!important`；确有宿主冲突时在适配层记录原因和最小选择器。宿主字体和可访问性偏好应通过适配层处理，不能强行改写整个 Obsidian。

### FF-02 / 色彩语义 / MUST

| 原色 | 主要用途 | 使用边界 |
|---|---|---|
| 枣红 `#982C3D` | 主要命令、选中、日间焦点、P0 | 小面积强调，不做分区大底或所有辅助标签 |
| 深蓝 `#103B64` | 标题、信息、图表结构、P2 | 不形成第二套选中/保存按钮逻辑 |
| 深绿 `#155641` | 成功、完成、进度填充 | 不用作新建/保存或装饰浅绿底 |
| 橙色 `#E86512` | 警告、截止提醒、P1 | 不作正文文字或大面积底色 |
| 中性白灰黑 | 画布、表面、正文、标签、边界、轨道 | 不使用带色相的“近似灰” |

只保留 `palette-1`；米白 `#EBD0AD` 退出。禁止浅翠绿、浅蓝、粉色等有彩衍生色，也不使用品牌色 alpha、opacity、color-mix 生成新颜色。金额以名称、正负号表达，不按收入/支出自动染红绿。图表还须配图例、标签或形状。

四种原色冷暖能形成平衡；成立条件是白灰主导、枣红为唯一交互强调、绿橙按语义出现。大块相邻红绿容易产生节庆联想，红橙叠加强调容易急促。对比度能检验可读性，不能证明审美优劣。

### FF-03 / 明暗与可读性 / MUST

Obsidian 默认跟随宿主，网页默认跟随系统；手动设置优先。适配器只输出一个 `effectiveMode`，组件不各自读取媒体查询或宿主 class。日间主导航白底，夜间中性深灰底。

夜间深蓝、深绿、枣红用作小面积底色并配白字，不能直接用作深底小字；橙底使用近黑 `#161616`。普通文字对比度至少 4.5:1，大字与识别控件所需的边界/图形至少 3:1；禁用与装饰元素按适用范围判断。照片文字独立验证，不能泄漏进背景选择器。

已测组合：白字/枣红约 7.60:1、白字/蓝 11.47:1、白字/绿 8.59:1、近黑/橙 5.43:1。枣红/夜间 `#252525` 仅 2.02:1，不可作小字；夜间进度轨道 `#BDBDBD` 与绿约 4.58:1。验收仍看实际计算样式。

### FF-04 / 实色内容与轻量层级 / MUST

弹窗、菜单、输入、卡片、表格内容使用无 alpha 表面，禁止玻璃与 backdrop-filter。透明只允许用于内容之外的遮罩与投影。

页面区块靠标题、间距、实色底组织；导航、侧栏区块、统计指标、图表不逐个画四边外框。表格只保留必要横向行分隔，不画每格围栏；同底嵌套内容不重复套框。卡片用于独立重复项目或需要边界的工具，不能把整页拆成层层卡片。

输入保留 1px 可识别边界，焦点轮廓必须清楚。弹窗只留外层边界，正文不再框一层。**去除装饰线，不降低必要控件和文字对比度。**

### FF-05 / 尺寸、字体与稳定性 / MUST

| 项目 | 默认值 |
|---|---|
| 字体与字距 | 系统无衬线 / PingFang SC；字距 0 |
| 工具 / 页面 / 弹窗标题 | 16/24、20/28、18/26px |
| 正文控件 / 辅助表头 / KPI | 13/20、12/18、24/30px |
| 间距 | 4、8、12、16、24、32px |
| 圆角 | 面板/导航 8px，控件 6px，优先级 999px |
| 控件 / 图标按钮 / 表格行 | 高 32px / 32×32px / 默认高 40px |
| 图标与数字 | Lucide 16px；金额等宽数字、右对齐 |

标签到输入 4px，控件间 8px，字段间 12px，区域内边距通常 16px，分区间 24px。加载、悬停、标签长度不得改变工具栏/按钮/图表尺寸。长内容允许增高，不强行固定所有行高。禁止按视口压缩字体。

### FF-06 / 命令与状态语义 / MUST

每操作区最多一个 primary，使用枣红底白字。普通命令中性底，完成状态用绿；删除使用明确文字与图标，默认中性底，在确认危险操作时才强调。不能只靠颜色区分选择、错误、成功与风险。

所有页面同一优先级配方：P0 枣红白字、P1 橙底近黑、P2 深蓝白字、P3 中性底次级字；均为胶囊。状态按语义分配，不按模块轮流分色。

### FF-07 / 字段与自适应 / MUST

字段有永久 label 并与控件关联，占位文字不能替代 label。错误说明具体原因与修正方法，并通过 `aria-describedby` 关联。布局列使用 `minmax(0, …)` 等可收缩轨道，字段 `min-width:0`，控件 `box-sizing:border-box`。

下拉按实际选项文字测宽、左对齐、视口夹取且至少留 8px 边距，长文本换行；不继承旧模块 `min-width:100%` 的全屏撑宽。窄窗换行或组件内部横向滚动，不能整体溢出、遮住操作、裁掉重要文字。若支持触屏，关键操作命中区至少 44px；窄屏预览不等于手机平台支持。

### FF-08 / 键盘与弹层生命周期 / MUST

图标工具有名称、tooltip 和可见焦点；二元设置用开关/复选框，模式用分段控件，选项集用菜单，工具用熟悉图标。Tabs 视觉选中与 `aria-selected` 一致，交互能通过键盘完成。

Dialog 合理首次聚焦、锁定模态焦点、Esc 关闭、关闭回焦。嵌套下拉先响应 Esc，第二次才关闭弹窗。正文可滚，底部操作可达。Menu 支持键盘、Esc 与外部点击关闭，不被父级裁切。适配层使用元素 `ownerDocument/defaultView` 与 Obsidian Scope，支持独立窗口；销毁时清理监听和定时器。

### FF-09 / 真实反馈与保存 / MUST

局部修改进入保存队列后立即通知界面；保存 Promise 仍等待持久化与回读校验，失败继续传播并提示，不冒充“已保存”。重复提交必须防护；适用的异步操作提供 pending/success/error，加载不造成布局跳动。空状态给可执行入口，失败给修正或重试，不伪造数据。

指针进入下拉只更新新旧两项；只有键盘导航才将选项滚入菜单可见区，不牵动整页。昂贵扫描与 I/O 不应阻塞一次点击的视觉反馈。

### FF-10 / 动效与性能证据 / SHOULD

控件变化通常 120ms，弹层 160ms；遵循 reduced-motion，不为了动画等待保存。性能目标：代表性本地操作的点击到可见反馈 p95 ≤100ms；记录机器、数据量、场景、样本数与测量起止点。此为新目标，**当前没有完整 p95 基准**。保存耗时单独测，不承诺磁盘写入 100ms。

上轮局部样本：变更通知从 353–555ms 降到 4–22ms，只证明通知链改善，不能推导整款插件性能达标。排查迟滞先测事件处理、渲染、扫描、保存各阶段，不靠删校验或备份换速度。

## 4. 组件状态契约

| 组件 | 检查状态/行为 | 共享归属 |
|---|---|---|
| Button / IconButton | default、hover、active、focus、disabled、适用的 pending；名称与防重复提交 | `components.css` |
| Field | normal、focus、error、disabled；label、错误关联、越界 | `fields.ts` + 公共样式 |
| Select / Menu | 空结果、长选项、键盘、边缘定位、Esc、回焦 | `select.ts` / `menu.ts` |
| Tabs / Navigation | 选中一致、键盘可达、长名称、明确单行/滚动策略 | 公共样式 + 页面导航 |
| Dialog | 主题、首次焦点、锁焦、嵌套 Esc、回焦、长表单滚动 | `modal.ts` |
| Table / Chart | 正常、空、加载、失败；表头图例、金额对齐、内部滚动 | 公共样式 + 业务数据 |
| Status / Priority | 语义一致、文字或图标线索、四级优先级 | 公共样式 |

适用状态是实现要求，不给纯静态元素强加 loading。共享样式入口不等于已完成独立组件封装；新增能力优先扩展公共实现。

## 5. 非凡人生专属布局

| ID | 页面契约 |
|---|---|
| LIFE-01 | 总览模块按实际数量等分，始终同一行；不留半空第二行；长字可换行 |
| LIFE-02 | 习惯顶部仅具体习惯、桌面两列；中间热度与进度左右分布；底部趋势通栏。小于 700px 前两层改单列；热度标题到第一条习惯至少 24px |
| LIFE-03 | 个人/生意账本五项指标使用同一实色带，不逐项套框或染底 |
| LIFE-04 | 主导航仅总览、任务、规划、财务、清单、习惯、灵感、复盘；不恢复词元界面/扫描，保留历史字段兼容 |
| LIFE-05 | 背景内置可离线分发且许可明确的照片，记录来源；默认遮罩保证文字可读。纯色与自定义图片可选，切换预设不丢失自定义路径；照片不成为新的界面配色 |
| LIFE-06 | 复盘有明确新建入口与共享实色表单；日期、保存目录和四段内容可编辑。同日已有文件改为打开原文，禁止覆盖；保存成功后展示并打开笔记，失败保留输入并反馈 |

## 6. 验收与变更流程

1. 定义用户、数据、操作及适用规则 ID；先复用组件，缺失能力再扩展公共组件。
2. 大面积视觉调整先网页评审；网页导入正式源码，不维护另一套样式。
3. 对受影响组件检查正常/空/失败/禁用/焦点和适用加载；增加长中文、长选项、极端金额、无数据案例。
4. 主题/公共组件变更执行完整矩阵；局部变化检查受影响范围与共享调用方。结果记录版本、场景、时间、限制、证据路径。
5. 插件代码执行 `typecheck`、`build`，构建与部署分离；视觉变更不改业务数据。数据迁移单独设计备份、回读及失败恢复。

完整矩阵：17 视图 × 日/夜 × 1600×1050、1024×768、390×844 = 102 个浏览器组合。任务 2、规划 2、财务 5、清单 4，总览/习惯/灵感/复盘各 1；额外覆盖财务个人/生意上下文及弹窗。34 组模式/视图检查实际颜色；任务、财务、清单、规划、习惯、灵感弹窗检查主题与生命周期，必要时覆盖独立窗口。390px 是布局压力测试，当前插件仍为 desktop-only。

本产品副本不包含个人工作台及历史快照。**含真实数据的快照、截图不得直接作为公开演示。** 公开演示使用合成数据，发布条件另见 [发布准备清单](发布准备清单.md)。

## 7. 明确待完善项

以下不能宣称已统一完成：通用脏表单关闭确认；全部异步操作 pending/error 防护；全组件键盘/辅助技术审计；代表性 p95 性能基准；大型数据集扫描与保存测试；公开发布所需的宿主主题/snippet、Windows/Linux、最低 Obsidian 版本验证；框架无关的独立组件包。

## 8. AI 短指令与版本管理

先读本文件、`ui-contract.json`、生成的 `design-tokens.json` 和实际共享组件。列出适用规则 ID；修公共来源并移除旧定义；不恢复旧皮肤、透明内容、浅翠绿或页面专属配方。交付区分要求、实现、已测与待办。业务记录不随 UI 删除。

1.1 增加规则 ID、核心/业务边界、状态契约、性能目标与证据区分、公开演示数据边界；已确认配色不变。破坏组件语义或品牌关系的变更提升主版本并给迁移说明。JSON 与视觉文档同步；token JSON 为生成的索引，以正式 CSS 为唯一来源，更新时从 CSS 重新提取，不手改色值。
